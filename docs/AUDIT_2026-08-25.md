## 4. 当前发现

### Critical

#### C-1:`.github/`、`tests/`、`CHANGELOG.md`、`CONTRIBUTING.md`、两份历史审计报告均未纳入 Git

**证据:** `git status` → `?? .github/`、`?? tests/` 等 10 个未跟踪路径;`origin/main` 无 workflow。

**影响:** 本报告验证的 CI 规则(SHA-pinning、permissions、brand-check)对远端完全不存在;任何人 clone 后拿到的仓库没有这些保障。这是供应链意义上的「审计与部署不一致」。

**建议:** P0,按逻辑拆分提交(CI 一个 commit、tests 一个 commit、docs 一个 commit),推送后观察一次 hosted run。

#### C-2:LoopX runtime registry 被 Git 跟踪且含本机绝对路径(继承自 8-18 C4)

**证据:** 见第 2 节实测输出;registry.json 含 `/Users/jie/.codex/loopx`、`/Users/jie/code/EricStack`。

**建议:** P0,`git rm --cached .loopx/registry.json` + `.gitignore` + 提供去隐私化 example fixture。涉及 Git 跟踪边界,需用户决策后执行。

### High

#### H-1:uninstall-ericsstack.sh 交互确认可被管道输入绕过

**证据:** uninstall-ericsstack.sh:119 使用裸 `read -r -p`;全文件无 `[ ! -t 0 ]` 防护。对照 sync-skills.sh:374-384 有完整的非 TTY fail-closed。

**复现:** `echo y | bash .loopx/bin/uninstall-ericsstack.sh` 将直接删除 43 个受管项而无人工确认。

**建议:** 移植 sync-skills.sh 的 TTY 检查模式。

#### H-2:sync 供应链声明 checksum 校验但从未实现(继承自 8-18 H2)

**证据:** sync-state.json `sync_policy.checksum_verify: true`;sync-skills.sh 中无任何 checksum/signature 逻辑;clone 后直接 sed 改写并 rsync 入库。另:浅克隆 HEAD 与 state 写入之间存在并发窗口(clone 后上游再 push,state 记录的是克隆时 HEAD)。

**建议:** 实现 commit 固定 + 导入文件 allowlist/checksum + staging 原子切换;或在实现前把声明改为 false 并注明。

#### H-3:计数漂移大面积存在于 checker 覆盖范围之外

`check-skill-counts.sh` 只保护 headline 数字,以下位置漂移未被拦截:
