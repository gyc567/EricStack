# brain.md Integration

This document is the user-facing reference for the brain.md vendor
integrated into EricStack. It covers **why** we vendored, **what** the
boundary is between brain and EricStack's other memory facilities,
**how** to use it day-to-day, and **how** maintainers bump the vendor.

## What this is

`mindmux/brain.md` is a persistent, file-based memory layer for coding
agents. It captures durable project decisions, requirements, and
constraints as plain Markdown that lives in git and survives sessions,
branches, and agents. EricStack vendors it so you get that capability
without installing a separate npm package or trusting an external CLI
binary — the source lives in this repository and is pinned to a
specific commit (currently `dafdde9d9981895b149d6285ef19fa2ea9092747`,
see `.loopx/sync-state.json#sources.mindmux-brain-md`).

**License**: Apache-2.0. See `THIRD_PARTY_LICENSES.md` for the full
provenance, SHA-256 hashes of vendored files, and modifications
(none — every vendored file is byte-identical to upstream).

## Why we vendored and didn't depend on npm

- **Single delivery.** Installing EricStack gives you brain.md. No
  second install step, no `package.json` to keep aligned.
- **Auditable.** Every byte of the CLI is in the repo, SHA-256 pinned,
  inspectable without `npm` knowledge.
- **License-clean.** Apache-2.0 is permissive; we preserve the
  upstream license verbatim and ship the full text in
  `THIRD_PARTY_LICENSES.md`.

The cost is a one-time vendor bump whenever mindmux/brain.md ships a
release. See [Maintainer: vendor bump procedure](#maintainer-vendor-bump-procedure)
below.

## Boundary table — what goes where

EricStack now has three durable facilities for capturing knowledge:

| Facility | Scope | Lifetime | File format | How to write |
|---|---|---|---|---|
| **brain** | Project-level decisions, constraints, concepts, references | Indefinite (in git history) | One page per topic, with append-only timeline | `brain` CLI (the only writer) |
| **context-save** | This session's working state — task, decisions-in-progress, next steps | One session; superseded on next save | One file per save, `YYYYMMDD-HHMMSS-<title>.md` | Skill writes the file directly |
| **.loopx/wiki/** | Auto-generated knowledge graph of EricStack itself | Tied to EricStack source | Static Markdown, `concepts/` `entities/` `queries/` | Read-only (regenerated by tooling) |

Use the test: **"Will this still matter in six months, and is it hard
to reconstruct from the code itself?"**

- If yes → **brain**.
- If it's about *this* session → **context-save**.
- If it's about EricStack itself → leave it to the wiki regen.

### Concrete examples

| You want to... | Use |
|---|---|
| Save "today I started implementing X" | `context-save` |
| Record "we chose PostgreSQL over SQLite for concurrent writes" | `brain create-page --category decision` |
| Pin an external RFC or postmortem | `brain create-page --category reference` |
| Carry "next steps for this session" across a long lunch break | `context-save` |
| Carry "the team agreed no new dependencies without RFC" across years | `brain create-page --category decision` |
| Understand EricStack's own concept model | read `.loopx/wiki/` |

## Installation state

`brain` ships with EricStack. After `install-ericsstack.sh` completes:

```bash
ls ~/.claude/skills/ | grep brain
# brain-page       <- renamed on install (CLI requires this exact name)
# brain-setup      <- renamed on install (CLI requires this exact name)
# erics-ability-brain-init       <- symlink (operational body)
# erics-ability-brain-page       <- symlink (alias of brain-page, same content)
# erics-ability-brain-bootstrap  <- symlink (operational body)
# erics-ability-brain-ingest     <- symlink (operational body)

which brain
# ~/.local/bin/brain -> ~/.claude/skills/brain-page/bin/brain.mjs
# or ~/bin/brain if ~/.local/bin/ doesn't exist
```

The CLI is on your PATH if `~/.local/bin` (or `~/bin`) is. If not,
add it or invoke directly:

```bash
node ~/.claude/skills/brain-page/bin/brain.mjs <subcommand>
```

The `~/.claude/skills/brain-page/` and `~/.claude/skills/brain-setup/`
directories **must exist as siblings** — that's an upstream CLI
constraint, not an EricStack choice. The install script materializes
this; if you ever see `init cannot find scaffold assets at ...`, it
means `brain-setup` is missing or one of them was moved.

### Verifying your install

```bash
brain brain-dir          # should print a path, "default" or "brainRoot"
brain list-pages         # works only after `brain init` in a project
node ~/.claude/skills/brain-page/bin/brain.mjs --help
```

## Day-to-day usage

#### First time in a project

```bash
cd /path/to/your-project
# 1. Initialize the brain (one-time, per project)
brain init

# 2. Either bootstrap from code/git log, or seed manually:
brain --help           # see all subcommands
```

#### Capturing a decision you just made

```bash
brain create-page \
  --id decision-postgres-over-sqlite \
  --category decision \
  --title "Use PostgreSQL not SQLite for the config store"

# Then write the compiled_truth via stdin:
cat <<'EOF' | brain update-truth --id decision-postgres-over-sqlite --summary "team agreed"
We chose PostgreSQL over SQLite.

Reasons:
- Concurrent writers (we expect >10 w/s at peak).
- JSONB columns for flexible config schema.

Rejected:
- SQLite (single-writer contention above ~10 w/s).
- etcd (operational overhead vs. our scale).
EOF

# Always reindex after writing:
brain reindex && brain lint-links
```

#### Reading before starting a task

```bash
brain list-pages                    # scan the table of contents
brain read-page decision-postgres-over-sqlite
brain read-root architecture        # one of the six root pages
```

#### Promoting session decisions to project memory

When `/context-save` writes a checkpoint, **Step 5** of that skill
will offer to sync architectural decisions into brain. Use it; ignore
it; or disable with `echo 'brain_prompt: never' > .brainrc` at the
project root.

## Constraints you should know

### Cross-platform support

The vendored CLI is Node.js (`bin/brain.mjs`), uses
`process.cwd()` / `fs.promises` / `node:url` imports, and requires
Node ≥ 18 on `PATH`. **Verified on macOS and Linux**. Windows requires
manual confirmation that Node is on `PATH`; EricStack does not
guarantee Windows support for the brain vendor.

If you see `node: command not found`, install Node 18+ first
(e.g. `brew install node` on macOS, `nvm install 18` on Linux).

### Concurrency semantics

brain is git-tracked Markdown, not a database. `update-truth` is one
atomic `fsync` per call (the CLI writes the file in a single
`writeFileSync`). If two EricStack skills run `update-truth` on the
same page concurrently:

- Last write wins on `compiled_truth`.
- Both timeline entries are preserved (the CLI appends a `decision`
  entry on each `update-truth`).
- Older `[[page-id]]` cross-references stay valid because pages are
  never deleted (use `archive-page` to mark them historical, never
  `rm`).

If you need strict ordering, run brain operations serially from one
context (e.g. one skill invocation). If you need concurrent
merge semantics, that's outside brain's design — use git for that.

### DeepSeek Harness projects — never run brain-init/bootstrap

If a project contains `notes/implemented/` or `notes/archived/`, it
uses the DeepSeek Harness Agent Notes system. Running brain-init or
brain-bootstrap there creates **two competing decision corpora** and
contradictions within a few days. The HARD GATE in
`erics-ability-brain-init`, `brain-bootstrap`, and `brain-ingest`
refuses to operate on such projects; use
`/erics-process-archive-agent-notes` instead.

### Don't hand-edit brain files

The CLI is the sole writer by design. Frontmatter invariants and the
`compiled_truth` ↔ timeline atomicity are guaranteed by construction, not
by a validator. Hand-editing breaks parsing on the next
`read-page` and breaks `update-truth` atomicity guarantees.

If you absolutely must edit (e.g. emergency data recovery), write a
note in the page's timeline explaining the manual intervention before
running any CLI command again, so future readers see the discontinuity.

### Uninstalling EricStack never touches your project's brain data

`uninstall-ericsstack.sh` removes `~/.claude/skills/brain-page/`,
`brain-setup/`, and the four `erics-ability-brain-*` skills. It does
**not** remove your project's `BRAIN.md` or `brain/` directory — those
are user data and the upstream protocol treats them as such. To remove
them manually: `rm BRAIN.md brain/` from the project root.

## Maintainer: vendor bump procedure

When `mindmux/brain.md` ships a release you want to pick up:

```bash
# 1. Pull upstream
git clone --depth=1 https://github.com/mindmuxai/brain.md.git /tmp/mindmux
cd /tmp/mindmux && NEW_COMMIT=$(git rev-parse HEAD)
echo "New commit: $NEW_COMMIT"

# 2. Read release notes / breaking changes
open https://github.com/mindmuxai/brain.md/releases

# 3. Vendor the new CLI + template
cp /tmp/mindmux/skills/brain-page/bin/brain.mjs \
   EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/bin/brain.mjs
cp /tmp/mindmux/skills/brain-page/lib/brain.mjs \
   EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/lib/brain.mjs
cp /tmp/mindmux/skills/brain-setup/assets/BRAIN.md \
   EricStack/.loopx/skills/erics-ability/erics-ability-brain-setup/assets/BRAIN.md

# Optional: vendor hooks (only if release notes recommend them)
# cp /tmp/mindmux/skills/brain-setup/hooks/pre-commit \
#    EricStack/.loopx/skills/erics-ability/erics-ability-brain-setup/hooks/
# cp /tmp/mindmux/skills/brain-setup/hooks/session-start \
#    EricStack/.loopx/skills/erics-ability/erics-ability-brain-setup/hooks/

# 4. Update .loopx/sync-state.json: bump commit, last_sync,
#    re-record SHA-256 of every changed file, set installed_by_default
#    on hooks if you vendored them.

# 5. Validate
node --check EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/bin/brain.mjs
node --check EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/lib/brain.mjs
shasum -a 256 EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/bin/brain.mjs \
             EricStack/.loopx/skills/erics-ability/erics-ability-brain-page/lib/brain.mjs \
             EricStack/.loopx/skills/erics-ability/erics-ability-brain-setup/assets/BRAIN.md

# 6. Run pre-push checks
bash .loopx/skills/erics-process-pre-push-checks  # if exposed as script; otherwise read SKILL.md

# 7. Smoke test in an isolated HOME
mkdir -p /tmp/brain-bump-test/.claude/skills /tmp/brain-bump-test/.local/bin
HOME=/tmp/brain-bump-test SKILLS_DEST=/tmp/brain-bump-test/.claude/skills \
  bash EricStack/.loopx/bin/install-ericsstack.sh
PATH=/tmp/brain-bump-test/.local/bin:$PATH brain --help
PATH=/tmp/brain-bump-test/.local/bin:$PATH brain init --no-wire  # in a fresh dir
PATH=/tmp/brain-bump-test/.local/bin:$PATH brain create-page --id bump-test \
  --category decision --title "Bump smoke test"
PATH=/tmp/brain-bump-test/.local/bin:$PATH brain read-page bump-test
rm -rf /tmp/brain-bump-test /tmp/brain-bump-test/.local/bin/brain

# 8. Commit
cd EricStack && git add -A
git commit -m "chore(brain): vendor bump mindmux/brain.md \$OLD_COMMIT..\$NEW_COMMIT"
git push
```

If the upstream CLI changes its sibling path convention (e.g. from
`brain-setup` to something else), PR-3's install script will need to
update its hardcoded renames. The smoke test in step 7 will catch that
early.
